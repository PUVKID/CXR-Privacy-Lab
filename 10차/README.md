## LEVEL 1 - Beginner

| 말 | 뜻 | 화면에서 확인할 것 |
| --- | --- | --- |
| 모델·초기화 | 사진의 특징을 수치로 학습하는 계산 장치와 그 출발값 | ImageNet은 일반 사진을 배운 출발점이며 조건별 CXR 학습 결과가 아님 |
| 검증·검색 | 두 사진이 같은 환자인지 판단·여러 후보에서 같은 환자를 찾는 두 과제 | 각각 별도 모델을 학습하고 NIH와 COVID 외부 결과를 구분 |
| 에폭·배치·손실 | 자료 한 바퀴·한 번에 처리하는 묶음·학습 오차 | 처리 배치 수가 가중치 적용 횟수나 정확도는 아님 |
| 새 초기화·재개 | 다른 조건은 처음부터, 같은 조건 중단은 검증한 저장점부터 | 대기·초기화 계획·실제 초기화 기록을 구분 |
| 블러·모자이크 | 주변을 부드럽게 섞기·작은 칸의 밝기로 뭉치기 | 원영상 픽셀 단위이며0강도 등 항등 조건도 별도 학습 |

사진은 원본 파일을 바꾸지 않은 채 선택한 강도로 변환되고, 그 사진에서 새 검증·검색 모델이 만들어집니다. 예를 들어 블러2에서 학습한 결과를 블러4 모델의 출발값으로 넘기지 않습니다. 화면에서 블러4를 고르면 블러4의 기록만 보며 아직 시작하지 않았으면 손실·평가는 미측정입니다.

| 설정 용어 | 쉬운 풀이 | 이번 조건 |
| --- | --- | --- |
| Adam·SGD | 틀린 정도를 보고 모델 수치를 조절하는 서로 다른 학습 방법 | 검증 모델은 Adam·학습률0.0001, 검색은 SGD·학습률0.158489 |
| OneCycle·학습률 | 모델을 얼마나 크게 고칠지 정한 값과 그 변화 계획 | 검색 단계 안에서 변화하며 다른 조건의 진행 상태를 넘기지 않음 |
| CBM128 | 최근 사진 특징을128개까지 기억해 비교하는 검색 학습 메모리 | 같은 조건 안에서 사용하며 원본 이식의 검증 중 갱신 정책도 유지 |
| AMP·배치32 | 계산 정밀도를 나누어 메모리를 아끼기·한 묶음32개 처리 | 표시된 처리 배치가 실제 가중치 적용 횟수와 항상 같지는 않음 |
| BN·activation checkpointing | 특징 통계를 기억하기·중간 계산을 다시 계산해 메모리를 아끼기 | 통계 버퍼 복구와 원래 학습 동작을 유지하며 배치 크기를 줄이지 않음 |
| seed3 | 난수의 출발점을 정하는 번호 | 같은 비교 조건이며 모든 장치에서 계산 결과가 완전히 같다는 보장은 아님 |

검증 모델은 최대100에폭까지 학습하되 검증 손실이 개선되지 않는 횟수가5번이면 일찍 끝납니다. 검색 모델은 출력부30에폭을 먼저 학습하고 같은 조건의 모델 전체를50에폭 학습합니다. 각 과정은 순서와 길이가 달라 세 단계의 막대를 평균 내어 남은 시간을 계산하지 않습니다. 정확도는 저장된 판정 결과이고 손실은 학습 오차이므로 손실을 정확도로 바꾸어 읽지 않습니다.

**강도별 학습은 강도마다 새 모델을 만드는 일**입니다. 흐리게 만든 사진의 강도 2와 강도 4를 비교한다면, 두 모델이 같은 출발점에서 각각 공부하게 합니다. 이미 공부한 모델 하나로 사진만 바꾸는 것은 강도별 평가입니다. 두 실험은 다른 질문에 답하므로 결과를 섞지 않습니다.

현재 원본 사진으로 학습 중인7차는 계속 둡니다. 새10차는 블러10조건과 모자이크10조건을 각각 따로 학습하도록 구성합니다. 원본 학습과 뒤따르는 평가가 모두 정상 종료되면 한 조건씩 실행합니다. 화면의 ‘원본 완료 대기’는 강도 모델이 이미 학습 중이라는 뜻이 아닙니다.

원본·블러·모자이크를 고른 뒤 강도 버튼을 누르면 그 조건의 상태와 기록을 봅니다. 에폭은 자료를 한 바퀴 도는 단위이고 배치는 한 번에 처리하는 묶음입니다. 아직 그 조건의 학습이 시작되지 않았다면 손실과 평가값은 미측정입니다. 다른 조건에서 나온 좋은 수치를 가져와 표시하지 않습니다.

초기값은 사진의 일반적인 특징을 배운 ImageNet 모델을 쓰되, 흉부 엑스레이를 학습한 다른 강도의 결과는 넘기지 않습니다. 0강도처럼 사진이 바뀌지 않는 조건도 실험 조건을 따로 기록합니다. 높은 환자 재식별 실패율이 익명성 전체를 보장하지 않으며, 새 학습을 구성했다는 사실과 모든 학습이 끝났다는 사실도 다릅니다.

## LEVEL 2 - Explorer

| 입력 | 처리 연결 | 출력과 조건 |
| --- | --- | --- |
| NIH 학습·검증 영상 | 해당 조건 변환 → 모델별 입력 크기·정규화 → 두 과제 학습 | 조건별 새 모델; COVID는 학습·선택에 쓰지 않음 |
| 조건 정의·같은 ImageNet·seed3 | 다른 조건의 상태를 넘기지 않고 새 프로세스에서 시작 | 같은 출발 수치는 의도한 통제이며 CXR 상태 공유가 아님 |
| 원본 전체 종료 근거 | 관리자 종료 코드·모델·NIH/COVID·고정모델 평가 확인 | 모두 정상이어야20조건 순차 실행, 불명확하면 차단 |
| 같은 조건의 두 검색 단계 | 출력부 학습 → 자체 가중치로 전체 학습 | 조건 내부 승계이며 다른 강도 모델의 재사용과 다름 |

옵티마이저는 손실을 보고 가중치를 조절하는 장치이고 스케줄러는 학습률을 바꾸는 계획입니다. 검색 메모리(CBM)는 최근 특징을 보관해 비교에 쓰는 큐입니다. 이 상태들까지 조건 사이에서 분리해야 ‘사진만 바꾸어 같은 모델을 시험한 것’과 다른 실험이 됩니다. 같은 조건의 검색 출력부에서 전체 네트워크로 이어지는 학습은 이 분리를 깨지 않습니다.

NIH 검증 모델의 원저자 목록은 학습75,708·검증10,816·시험25,596장이고 검색 학습 목록은61,755행입니다. 행 수를 독립 환자 수라고 바꾸어 읽지 않습니다. 모델 선택에 시험·COVID 자료를 사용하지 않으며 검증 판정 임계값은0.5입니다.4~6차의 정제 제외목록을 적용한 분모가 아니므로 원본의 동일 픽셀 중복과 다른 환자 표지 중복 한계가 남습니다. 검색에서 자기 원본 영상 하나를 제외하는 규칙이 다른 이름으로 된 모든 중복까지 제거하는 것은 아닙니다.

**변환 조건 → 새 초기화 → 검증·검색 학습 → 해당 조건 평가**가10차의 흐름입니다. 기존7차의 원본 학습과 고정 모델21조건 평가는 보존합니다. 새 흐름은 변환된 영상에 맞춰 공격 모델도 다시 학습하는 별도 확장 실험입니다.

블러와 모자이크는 각0·1·2·4·8·16·32·64·128·256의10조건입니다. 숫자의 단위는 원영상 픽셀 조건이며, 모델의 입력 크기와 같은 개념이 아닙니다. 변환 뒤 모델별 입력 전처리를 적용합니다. NIH 학습 자료로 모델을 만들며 COVID-19는 외부 평가 자료입니다. 두 데이터셋을 각각 학습한다고 세지 않습니다.

조건 사이에서는 모델·옵티마이저·스케줄러·검색 메모리와 학습 난수 상태를 넘기지 않습니다. 비교에 쓰는 초기 가중치와 seed 기준은 같습니다. 한 검색 모델 안에서 출력부를 학습한 뒤 전체 네트워크를 이어 학습하는 것은 같은 조건의 내부 과정입니다. 다른 조건으로 넘어갈 때의 독립 초기화와 구별합니다.

대기열은 원본 관리자의 실제 종료와 정상 산출물을 함께 확인합니다. 학습 완료 기록 하나나 파일 존재만으로 원본 평가까지 끝났다고 판단하지 않습니다. 조건별 저장 폴더와 실행 식별자가 분리되어 화면에서 한 조건을 고르면 그 조건의 기록만 읽습니다. 기록이 없거나 맞지 않으면 수치를 보여 주지 않습니다.

## LEVEL 3 - Practitioner

| 순서 | 실제 준비·조작 | 확인과 실패 처리 |
| --- | --- | --- |
| 준비 | 합법적으로 확보한 NIH/COVID와 공식 목록·실행 환경·ImageNet을 준비 | 공개 저장소에 영상·목록·가중치·전체 운영 패키지는 없음 |
| 원본 확인 | 기존7차 학습·후속 평가를 유지 | 표시창을 닫는 일과 학습 관리자 종료·재부팅은 다름 |
| 대기열 | [학습 실행 안내](학습안내.md)의 준비·실행 조건 확인 | 실제 운영 식별자·관리자 생성시각은 로컬에서 검증, 오류를 무시해 시작하지 않음 |
| 조회 | 강도별 학습에서 조건 선택·원기록 펼침 | 해당 조건만 읽고 다른 조건 수치를 채우지 않음 |
| 검사 | `node --check server.mjs`, `node --test 검사/server.test.mjs` | 격리 합성 검사이며20조건 GPU 완주를 뜻하지 않음 |

현재 에폭 막대의 분모는 실제 배치 수입니다. 단계 막대는 최대 에폭 예정량을 기준으로 하므로 조기 종료·단계별 계산 시간의 차이를 포함한 시간 완료율이 아닙니다. 손실은 학습·검증 곡선을 나누어 읽고, 최근256KiB 밖의 자료를 전체 이력이라고 부르지 않습니다. 백분율은 한 자리 반올림이며 원비율을 펼쳐 확인합니다. 반올림100.0%와 실제 원비율1도 구분합니다.

**원본7차는 그대로 두고10차의 학습 실행 안내를 따릅니다.** 실행 전 데이터와 공통 실행 환경, ImageNet 초기값, 현재 원본 실행의 식별자와 상태를 확인합니다. 시작 명령은10차 학습 안내에 있으며, 대시보드는 읽기 전용이므로 화면 버튼을 눌러 학습을 시작하거나 종료하지 않습니다.

순차 실행기는 원본 학습·원본 평가·기존 변환 평가의 정상 종료를 기다립니다. 원본 관리자가 오류로 종료되거나 종료를 확인할 수 없으면 다음 조건을 학습 중으로 바꾸지 않습니다. 같은 대기열을 중복 실행하지 않으며, 원본 실행기나 Python 전체를 종료하는 것은 표시 창만 닫는 일과 다릅니다.

대시보드에서 원본 학습과 강도별 독립 학습을 나누어 확인합니다. 강도 목록의 조건을 선택하면 현재 단계, 에폭과 배치, 손실 기록, 초기화와 재개 정보를 확인합니다. 동일 조건의 중단 재개는 그 조건과 프로토콜이 일치할 때만 허용되며, 다른 조건의 체크포인트를 지정해 학습을 건너뛰지 않습니다.

원본 고정 모델의 블러·모자이크 평가는 기존 영역에서, 새 조건별 학습 상태는 독립 학습 영역에서 봅니다. 학습 시작 전·학습 진행 중·평가 전 상태에서 최종 성능을 읽어 내지 않습니다. 원비율·손실·학습률은 저장값을 유지하고 백분율 요약만 소수 첫째 자리로 반올림합니다. 의료 원영상·영상별 목록·가중치·운영 로그는 공개 저장소에 포함하지 않습니다.

## LEVEL 4 - Advanced

| 경계 | 구현 규칙 | 차단하는 혼입 |
| --- | --- | --- |
| 원본·독립 조건 | 고정7차 조회와10차 허용20ID 조회 분리 | 기존21고정모델 평가를 새20모델 성과로 재사용하지 않음 |
| 저장·지문 | 조건·실행·설정·단계 초기화·가중치·평가 결합 | 임의 경로, 다른 조건 체크포인트와 완료 기록 |
| 실행 관측 | 최근 진행과 PID·생성시각·명령·관리자 계보 결합 | 큐 행 하나나 오래된 training JSON만으로 실행 중 단정 |
| 응답·이력 | 선택 변경 즉시 비움·늦은 응답 거절·LF 단위 엄격 이력 | 이전 조건·이전 단계 곡선과 손상 레코드의 조용한 누락 |
| 완료 | 학습·평가 정상 종료와 두 모델·두 데이터셋 결과 결합 | 파일 하나의 존재를 전체 완료로 해석 |

조건 지문은 변환 정의를 묶고 전체 프로토콜 지문은 소스·설정·환경·공식 목록 등 재개 조건을 묶습니다. 화면의 조건 지문 검사는 실행기의 전체 학습 바인딩 검사를 대신하지 않습니다. 조회는 읽기 전용이며 Host·Origin·CSP·고정 경로 경계를 유지합니다. 실제 CIM 관측의 실패는 확인 불가로 남기고 학습 프로세스를 종료하거나 확인을 우회하지 않습니다.

**10차는 기존 소스와 운영 중인7차를 수정하지 않고 별도 계약·학습 사본·순차 실행기·읽기 화면으로 구성합니다.** 조건 식별자는 등록된20개만 허용하며, 조건별 실행 경계와 지문이 맞아야 체크포인트를 재개합니다. 원본 또는 다른 조건에서 학습한 모델 상태를 다음 조건의 초기값으로 쓰지 않습니다.

같은 조건의 검색 출력부→전체 네트워크 전환은 정상적인 내부 학습 연속성입니다. 조건이 바뀌면 모델과 학습 상태는 새로 생성합니다. ImageNet 초기값과 seed를 공통으로 쓰는 것은 비교 조건을 맞추기 위한 선택이며, 서로 다른 장치나 버전에서 비트 단위 동일성을 보장한다는 뜻이 아닙니다.

실행기 게이트는 원본 전체 정상 완료와 실제 프로세스 종료를 결합합니다. 원본 학습의 progress completed는 후속 평가 완료를 대신하지 않습니다. 큐의 대기·오류·실행 중 상태를 분리하고, 큐가 대기 중일 때 GPU에서 강도 학습이 진행되는 것으로 표시하지 않습니다. 오류를 무시하고 완료로 넘어가지 않습니다.

화면은 허용된 조건과 해당 실행 경계의 기록만 조회합니다. 조건을 바꿀 때 이전 값은 비우고 늦은 응답이 선택을 덮어쓰지 않도록 합니다. 최근 이력 범위와 원값을 유지하며, 불완전하거나 손상된 기록에서 곡선을 발명하지 않습니다. 실제 소스·검사·직전 비교는 아래10차 자료를 통해 확인하며, 전체 실험 완료와 검사의 성공을 구분합니다.

# 강도별 독립 학습과 원본 진행 화면 · 10차

**원본7차 학습을 유지하면서 블러10조건·모자이크10조건의 새 모델 학습을 별도로 조회**합니다. 9차의 진행·손실·원값·테마·모션 기능을 보존합니다. 화면은 읽기 전용이며, 실행기와 학습을 시작하거나 종료하는 API를 제공하지 않습니다.

| 대상 | 모델과 입력 | 화면에서 읽는 것 |
| --- | --- | --- |
| 원본7차 학습 | 기존 원본 목록으로 진행 중인 같은 실행 | 상단의 원본 에폭·최대 예정 단계 진행·학습/검증 손실 |
| 20조건 독립 학습 | 블러·모자이크 각각0,1,2,4,8,16,32,64,128,256 | 선택 조건의 별도 실행·초기화·체크포인트·진행·손실·완료 평가 |
| 고정 모델21조건 평가 | 원본에서 학습한 동일 모델로 여러 질의 변환을 비교 | 기존 2데이터셋×2과제×21조건=84개 상태; 독립 재학습 성과와 구분 |

좌측의 **강도별 학습**을 누르면 독립 조건 영역으로 이동합니다. 상단84개 상태는 원본 고정 모델의 평가 범위이고 새20조건 모델 학습의 완료 수가 아닙니다.

## 독립 조건을 읽는 순서

원본을 포함한 기존 학습·후속 평가 전체가 정상 완료된 뒤 독립 조건 큐를 순차 실행하는 설계입니다. 단순 프로세스 소멸이나 파일 존재를 정상 완료로 보지 않습니다. 원본 오류·실행기 신원 미확인·완료 근거 부재이면 GPU 실행이 차단됩니다. 화면에 큐 대기가 보인다는 것은 독립 모델이 이미 GPU에서 학습 중이라는 뜻이 아닙니다.

각 조건은 같은 ImageNet 출발점과 시드3으로 검증 모델과 검색 모델을 새로 만듭니다. 다른 조건의 CXR 가중치·optimizer·scheduler·CBM·난수 상태를 넘기지 않습니다. 자기 조건의 체크포인트 재개만 설정·실행·조건 지문을 확인한 뒤 허용하는 계약입니다. 같은 조건 안에서 검색 출력부 학습을 마친 모델을 검색 전체 단계로 넘기는 것은 정상적인 내부 승계이며, 다른 조건 상태의 승계와 구분합니다. 블러0·모자이크0/1처럼 변형이 없는 **항등 조건도 독립 실행**하며 원본 모델 학습 결과를 자동 재사용하지 않습니다. 초기화 계획과 실제 각 학습 단계의 초기화 원기록 존재를 구분합니다.

| 선택 영역 | 근거 | 미측정·오류 처리 |
| --- | --- | --- |
| 조건 버튼20개 | 고정 허용목록과 실제 큐 행 | 큐가 없으면 기록 대기; 원본 완료 대기는 실제 대기 상태일 때만 표시 |
| 현재 에폭·최대 예정량 | 해당 조건의 진행 기록과 원정수 분모 | 0·누락·범위 오류 분모는 미측정; 시간 완료율로 표시하지 않음 |
| 학습·검증 손실 | 해당 실행 events.jsonl의 최근256 KiB | 다른 조건/원본 기록으로 채우지 않으며 새 단계에서 이전 단계 곡선을 표시하지 않음 |
| 단계별 초기화·가중치 | 동일 조건·실행·프로토콜 지문이 맞는 원기록 | 파일 존재와 단계·성능 완료를 구분 |
| NIH/COVID 평가 | 현재 조건의 두 모델 SHA와 양과제 결과 결합 | 정상 완료 결합이 확인된 경우만 요약; 원값·분모는 아래에서 확인 |

조건을 바꾸면 이전 표시를 즉시 비우고 새 조건을 조회합니다. 이전 요청이 늦게 도착해도 선택 ID·요청 순번이 다르면 반영하지 않습니다. 선택 조건의 원기록에서 실제 상태와 오류·초기화·원값을 펼쳐 볼 수 있습니다. 조건별 새 모델 평가에서는 **질의와 갤러리 양쪽에 같은 변환 조건**을 적용하므로, 기존의 원본 모델·질의만 변형한 고정 공격 평가와 프로토콜이 다릅니다. 강도별 새 학습을 원 논문의 완전 동일 재현으로 표현하지 않습니다.

## 읽기 경계와 실제 실행 확인

서버는 고정된 `work/queue/state.json`에서20조건·정규 실행 UUID·정해진 `work/runs/<UUID>/training` 경계만 읽습니다. API는 허용 조건 ID를 받으며 임의 경로나 실행 UUID를 입력으로 받지 않습니다. 조건 전체 정의·시드3·새 초기화·상태 승계 금지와 지문을 검증하고, 학습 설정·단계별 초기화·가중치 목록·평가 결과를 같은 조건에 결합합니다. 입력 파일은 UTF-8과 크기·실제 경계를 검사하며 원본을 쓰거나 삭제하지 않습니다.

큐의 학습 상태만으로 현재 학습 중을 주장하지 않습니다. 최근 진행 기록과 실제 읽기 전용 프로세스 관측의 PID·생성시각·소스·출력·조건·관리자 계보를 함께 확인합니다. venv 실행기와 그 실제 Python 자식은 한 실행으로 묶습니다. 조회 실패나 오래된 기록은 실행 미확인으로 남깁니다. 현재 프로세스 관측을 위해 사용하는 것은 읽기 전용 CIM 조회이며 실행 중인 PowerShell이나 학습 프로세스를 종료하지 않습니다.

node --check server.mjs
node --test 검사/server.test.mjs

## 진행과 그래프를 읽는 방법

백분율은 소수 첫째 자리 반올림이며 원분자·분모·계산 원비율을 학습 수치 원값에서 확인합니다. 에폭·전체 에폭·배치·전체 배치가 정수 범위를 벗어나거나 분모가0/누락이면 막대는 미측정입니다. 조기 종료로 다음 학습 단계에 진입하면 최대 예정 비율이100%가 아니어도 이전 단계가 끝난 것입니다. 세 단계의 단순 평균을 전체 시간 진행률로 제시하지 않습니다.

최근256 KiB의 완성된 LF 행만 엄격 UTF-8/JSON/실행 경계로 검증합니다. 중간 손상이 있으면 손실 시계열을 채택하지 않습니다. 원본은 보존되며 잘린 앞부분과 작성 중 마지막 행은 따로 안내합니다. **이 그래프는 전체 학습 이력이 아닙니다.** 학습 곡선은 단계·에폭·시간 역전·누적 처리 배치 되감기에서 선을 끊습니다. 원값이0인 손실은 유효하고, 미측정 손실은 점을 만들지 않습니다. 축 눈금만4유효숫자로 줄여 쓰며 그래프 점 설명과 전체 학습 원값에는 저장 정밀도를 유지합니다.

현재 기록과 오류 전 마지막 정상 기록, 오래된 관측과 실제 프로세스 확인을 구분합니다. 선택 가중치 파일만으로 단계 완료를 단정하지 않습니다. 두 과제 순차 학습 설정에서 후속 단계 관측 또는 실제 전체 학습 종료와 가중치 존재를 결합합니다. 현재 에폭 남은 배치는 표시하지만 재개·검증·자료 읽기가 섞인 로그에서 속도나 남은 시간을 만들지 않습니다. 처리 배치는 AMP에서 생략되는 가중치 적용 횟수와 다릅니다.

## PowerShell 창과 학습 실행

표시 창과 실제 학습 프로세스는 별개일 수 있습니다. 이번 확인에서 기존 표시 창에는 학습 자식이 없었고 실제 숨김 실행기 아래의 학습 프로세스는 별도로 관측됐습니다. 이 사실을 모든 PowerShell 창을 닫아도 안전하다는 일반 보장으로 확대하지 않습니다. 실행기나 실제 학습 프로세스 트리를 종료하면 학습이 중단될 수 있습니다. 이 화면의 모션 정지는 화면 움직임만 멈춥니다.

## 실행과 검사

Node.js로 `server.mjs`를 실행하면 기본 로컬8787에서 화면을 제공합니다. 운영 서버 교체는 학습과 별개로 담당자가 수행하며 기존 학습 프로세스를 종료하지 않습니다. 시험 서버는 `createDashboard()`를 import하여8788 같은 별도 포트로 열 수 있습니다. 기본 실험 경계는 같은 프로젝트의 `7차`이며 UUID 포인터의 임의 경로를 따르지 않습니다.
