## LEVEL 1 - Beginner · 배경과 용어부터 읽기

[11/13시점 원격 설명(보존) · 같은 LEVEL 1](https://github.com/PUVKID/CXR-Privacy-Lab/blob/2434a1e29533a74b7acc60a6799c8da550c91ac7/2%EC%B0%A8/README.md#reading-level-1) — 당시 6차까지의 설명이며 현재 7·8차 관측과 구분합니다.

| 구분 | 이 차수에서 하는 일 | 처음 읽을 때 확인할 뜻 |
| --- | --- | --- |
| 목적 | 1차를 바꾸지 않고 논문·공식 코드·평가 구현을 대조한 읽기 전용 감사입니다.<br>학습기를 새로 실행한 차수가 아닙니다. | 배우는 작업인지 평가인지 먼저 구분합니다. |
| 입력 | 1차 평가 소스, 공식 Verification·Retrieval 목록, 논문·저자 코드와 통제된 합성 사례를 검토합니다. | 사진·목록·모델·설정의 역할은 다릅니다. |
| 처리 | 분할 범위, 임베딩 정규화, 실행별 결과 보존, 캐시 출처, 동률, 파일·환자 검사, 재개 다운로드, Windows 경로와 자원·지표 보고를 점검합니다. | 화면과 계산 프로그램을 혼동하지 않습니다. |
| 설정·조건 | 당시 대상은 공개 최종 CXR 모델 평가였습니다.<br>공식 검증용 목록과 검색용 목록은 서로 다르므로 한쪽 수량을 다른 쪽에 강제하지 않습니다. | 설정 숫자는 성능 숫자가 아닙니다. |
| 출력 | 실험 성능 대신 결함 위치·영향·수정 권고를 담은 감사 요약과 전체 비교를 남깁니다.<br>개인별 목록이 없는 공개 요약입니다. | 파일이 있어야 측정값을 읽을 수 있습니다. |
| 과거·현재 관측 | 손상 PNG와 잘못된 시험 환자 쌍이 통과하는 제어 사례 등을 확인했습니다.<br>공식 원본 목록에서 실제 학습 환자 유입이 있었다는 판정과는 다릅니다. | 이 차수에서 확인한 범위까지만 말합니다. |
| 한계 | 감사에서 문제를 발견한 것과 이를 고친 것은 다릅니다.<br>합성 계산·공개 모델 추론 성공을 실제 환자 데이터의 논문 재현으로 바꾸지 않습니다. | 후속 차수의 해결을 과거에 소급하지 않습니다. |
| 실행·검사 | 보고서의 근거와 제어 사례 원문을 대조합니다.<br>이 감사 자체에는 준비 →학습 →평가 실행 절차가 없습니다.<br>후속 구현은 3차 이후 문서로 분리합니다. | 공개 설명만으로 의료 실험을 실행할 수 있는지 확인합니다. |

**읽는 예:** 두 계산기에 같은 수를 넣었는데 답이 다르면 입력 규칙과 계산 순서를 비교합니다. 2차는 이와 같은 조사입니다. “감사”는 코드를 살펴 근거와 문제를 남기는 일이며, 모델을 새로 가르치는 작업이 아닙니다. 1차의 원본 파일을 고쳐 놓고 조사한 것처럼 기록하지 않습니다.

검증 목록은 사진 두 장이 같은 환자인지 판단하는 데 쓰고 검색 목록은 여러 후보의 순위를 정하는 데 씁니다. 용도가 달라 목록 수가 조금 다른 것을 곧바로 손상으로 판단하면 안 됩니다. 사진을 숫자 특징으로 바꾼 뒤 길이를 맞추는 정규화가 빠져도 순위가 달라질 수 있어, 화면 모양과 계산 조건을 함께 보았습니다.

손상된 그림을 일부러 넣어 검사가 막는지 확인한 것은 **통제된 결함 사례**입니다. 그것이 통과했다면 방어가 부족하다는 근거지만, 실제 공식 목록 전체가 손상됐다는 뜻은 아닙니다. 감사가 남긴 권고는 후속 차수의 구현·검사와 연결해 확인해야 합니다.

**결과 보고:** 저장된 측정값과 논문 기준을 구분합니다. 손실은 시험 정확도가 아니며 PrivacyScore @1은 고정 공격의 1 순위 실패율입니다. 이 값만으로 익명성·임상 효용을 보장하지 않습니다. 의료 영상·개인별 목록·모델 가중치·운영 원문은 공개하지 않습니다.

## LEVEL 2 - Explorer · 구성과 조건의 관계

| 구성 요소 | 연결되는 자료·조건 | 해석 경계 |
| --- | --- | --- |
| 목적 | 1차를 바꾸지 않고 논문·공식 코드·평가 구현을 대조한 읽기 전용 감사입니다.<br>학습기를 새로 실행한 차수가 아닙니다. | 경로의 목적을 정하는 계약입니다. |
| 입력 | 1차 평가 소스, 공식 Verification·Retrieval 목록, 논문·저자 코드와 통제된 합성 사례를 검토합니다. | 입력 출처가 바뀌면 결과 해석도 바뀝니다. |
| 처리 | 분할 범위, 임베딩 정규화, 실행별 결과 보존, 캐시 출처, 동률, 파일·환자 검사, 재개 다운로드, Windows 경로와 자원·지표 보고를 점검합니다. | 앞 단계 통과가 뒤 단계의 전제입니다. |
| 설정·조건 | 당시 대상은 공개 최종 CXR 모델 평가였습니다.<br>공식 검증용 목록과 검색용 목록은 서로 다르므로 한쪽 수량을 다른 쪽에 강제하지 않습니다. | 분모·모델·표시 조건을 분리합니다. |
| 출력 | 실험 성능 대신 결함 위치·영향·수정 권고를 담은 감사 요약과 전체 비교를 남깁니다.<br>개인별 목록이 없는 공개 요약입니다. | 상태·미리보기·지표는 다른 출력입니다. |
| 과거·현재 관측 | 손상 PNG와 잘못된 시험 환자 쌍이 통과하는 제어 사례 등을 확인했습니다.<br>공식 원본 목록에서 실제 학습 환자 유입이 있었다는 판정과는 다릅니다. | 관측과 기능 구현은 다른 증거입니다. |
| 한계 | 감사에서 문제를 발견한 것과 이를 고친 것은 다릅니다.<br>합성 계산·공개 모델 추론 성공을 실제 환자 데이터의 논문 재현으로 바꾸지 않습니다. | 같지 않은 조건은 비교에 명시합니다. |
| 실행·검사 | 보고서의 근거와 제어 사례 원문을 대조합니다.<br>이 감사 자체에는 준비 →학습 →평가 실행 절차가 없습니다.<br>후속 구현은 3차 이후 문서로 분리합니다. | 검사 도구의 역할을 구분합니다. |

감사는 **공식 계약→현재 구현→차이를 드러내는 사례→권고**의 관계를 설명합니다.

공식 검증용 목록 두 장이 검색 목록과 다르다는 사실은 수량 강제 오류를 설명하고, L2 정규화 차이는 거리·순위·Rank1 보수 점수까지 영향을 줍니다.

고정 결과 폴더와 출처 없는 캐시는 어떤 모델·데이터에서 나온 수치인지 흐릴 수 있습니다.

따라서 정확한 분모, 입력 무결성, 결정적 동률 처리, 실행별 보존을 서로 연결된 요구로 제시했습니다.

실제 목록의 누수 발견과 누수를 막는 검사의 부재는 다른 결론입니다.

**결과 보고:** 저장된 측정값과 논문 기준을 구분합니다. 손실은 시험 정확도가 아니며 PrivacyScore @1은 고정 공격의 1 순위 실패율입니다. 이 값만으로 익명성·임상 효용을 보장하지 않습니다. 의료 영상·개인별 목록·모델 가중치·운영 원문은 공개하지 않습니다.

## LEVEL 4 - Advanced · 설계 경계와 변경 영향

[11/13시점 원격 설명(보존) · 같은 LEVEL 4](https://github.com/PUVKID/CXR-Privacy-Lab/blob/2434a1e29533a74b7acc60a6799c8da550c91ac7/2%EC%B0%A8/README.md#reading-level-4) — 당시 6차까지의 설명이며 현재 7·8차 관측과 구분합니다.

| 구현 경계 | 보존하는 계약과 사실 | 변경 영향 |
| --- | --- | --- |
| 목적 | 1차를 바꾸지 않고 논문·공식 코드·평가 구현을 대조한 읽기 전용 감사입니다.<br>학습기를 새로 실행한 차수가 아닙니다. | 상태·제어·수치 계산의 책임을 분리합니다. |
| 입력 | 1차 평가 소스, 공식 Verification·Retrieval 목록, 논문·저자 코드와 통제된 합성 사례를 검토합니다. | 출처 결합과 입력 검증의 경계입니다. |
| 처리 | 분할 범위, 임베딩 정규화, 실행별 결과 보존, 캐시 출처, 동률, 파일·환자 검사, 재개 다운로드, Windows 경로와 자원·지표 보고를 점검합니다. | 실패 전파와 결과 격리를 검토합니다. |
| 설정·조건 | 당시 대상은 공개 최종 CXR 모델 평가였습니다.<br>공식 검증용 목록과 검색용 목록은 서로 다르므로 한쪽 수량을 다른 쪽에 강제하지 않습니다. | 재현 조건·설계 차이의 일부입니다. |
| 출력 | 실험 성능 대신 결함 위치·영향·수정 권고를 담은 감사 요약과 전체 비교를 남깁니다.<br>개인별 목록이 없는 공개 요약입니다. | 출력 계약을 바꾸면 소비자 검사도 필요합니다. |
| 과거·현재 관측 | 손상 PNG와 잘못된 시험 환자 쌍이 통과하는 제어 사례 등을 확인했습니다.<br>공식 원본 목록에서 실제 학습 환자 유입이 있었다는 판정과는 다릅니다. | 증거의 범위를 유지합니다. |
| 한계 | 감사에서 문제를 발견한 것과 이를 고친 것은 다릅니다.<br>합성 계산·공개 모델 추론 성공을 실제 환자 데이터의 논문 재현으로 바꾸지 않습니다. | 남은 위험과 의도된 변경을 구별합니다. |
| 실행·검사 | 보고서의 근거와 제어 사례 원문을 대조합니다.<br>이 감사 자체에는 준비 →학습 →평가 실행 절차가 없습니다.<br>후속 구현은 3차 이후 문서로 분리합니다. | 구조·실제 동작·모델 성능 검증을 구별합니다. |

**감사 경계:**정규화 전후 거리, 동률 전순서, 불변 출처에 결합한 캐시, 실행별 출력 격리가 독립 항목이 아니라 결과 신뢰성의 연쇄 조건임을 봅니다.

검증 시험 환자 gate는 검색 시험 환자 집합으로 대신할 수 없습니다.

다운로드 Range·416·추출 복구, 디코드·픽셀 중복·바이트 해시는 서로 다른 보장입니다.

VRAM·공간 사전 검사와 EER·신뢰구간·그래프 글꼴/음수 표시는 재현 보고 계약입니다.

감사는 재현을 승인한 문서가 아니라 어떤 수리를 검증해야하는지 정리한 근거입니다.

**결과 보고:** 저장된 측정값과 논문 기준을 구분합니다. 손실은 시험 정확도가 아니며 PrivacyScore @1은 고정 공격의 1 순위 실패율입니다. 이 값만으로 익명성·임상 효용을 보장하지 않습니다. 의료 영상·개인별 목록·모델 가중치·운영 원문은 공개하지 않습니다.

## 2차 — 평가 재현 정밀 감사

1차를 수정하지 않고 원 논문과 공식 코드를 대조했습니다.

당시 경로는 공개 최종 CXR 가중치 평가였으며 재학습은 아니었습니다.

공식 Verification·Retrieval의 서로 다른 목록 범위, 검색 출력 정규화 누락, 고정 결과 덮어 쓰기, 캐시 출처 부족과 동률·파일 검증·Windows 실행 경로 문제를 확인했습니다.

합성 계산과 공개 모델 추론 검사는 실제 환자 데이터의 논문 성능 재현과 구분했습니다. 프라이버시 수식은 고정 공격에서의 Rank-1 실패율로 한정해야 하며, 자기 원본 제외와 환자 분할 검사 외에 전체 영상 검증이 필요하다고 판정했습니다. 공개판은 식별자·영상 목록이 없는 감사 요약입니다.
