# Original-paper fidelity and documented differences

Packhäuser et al., *Deep learning-based patient re-identification is able to exploit the biometric nature of medical chest X-ray data*, Scientific Reports 12,14851 (2022). https://doi.org/10.1038/s41598-022-19045-3

Author source: https://github.com/kaipackhaeuser/CXR-Patient-ReID/tree/880168f564afa07936a8d8fb3b868b140ab937d9

This is an independent Windows/PyTorch2 port for the existing NIH and COVID datasets, **not a claim of historical binary equivalence or achieved published performance**. The reference source/license are in `official_source/`; final CXR weights and Git/LFS metadata are not included or used for initialization.

## Preserved choices

- Exact author NIH image/pair/train/validation/test manifests, guarded by SHA-256 and counts. No revised split, new fold, reduced subset, cleaned projection or duplicate removal is silently introduced. Original duplicate-image caveats remain.
- NIH training/internal evaluation; COVID-19 Image Data Collection external test only. CheXpert is omitted as requested, not merged into the other datasets.
- ResNet-50 ImageNet initialization `resnet50-19c8e357.pth`, exact digest checked. No CXR6 weights or published final CXR model substitutes for new training.
- Verification topology, RGB/normalization/resize256, batch32, Adam1e-4, BCE-with-logits, max100 epochs, patience5 and best-validation-loss selection.
- RNP for the strongest published verification result: positive pairs retained, negatives re-sampled for both training and validation each epoch. The illustrative author config also has a `balanced` option; this package intentionally selects RNP.
- Retrieval topology/128-dimensional head, RGB/normalization/ColorJitter, resolution1024, batch32, SGD momentum0.9, weight_decay1e-5, OneCycle maxLR0.158489, 30/50 epochs, block-mining8, CBM128 and native mixed precision.
- Actual **unmodified pytorch-metric-learning0.9.94** contrastive/CBM code, vendored under `src/training/_vendor/`, upstream commit `f04e38c496c5c271381bb559795cd32ae4f68744`. Loss/gradient equivalence is tested on FP32/FP16 fixtures including queue wrap.
- Phase1 freezes backbone parameters while retaining original running-BatchNorm behavior. Phase2 starts from phase1's final-epoch model and trains the entire model. Retrieval uses each phase's final epoch, not a test-selected epoch.
- Original two retrieval sanity-validation batches and validation batch32. The original source **updates the same CBM queue during validation**; this is retained. Disclose this limitation rather than calling it a newly leakage-free design.
- Native AMP overflow skips that optimizer update and reduces the scale; scientific training batches are not replayed.
- Original cuDNN policies: verification benchmark enabled; retrieval deterministic enabled. TF32 disabled because the original V100 lacked that numeric path.
- Verification decision is strictly `score > 0.5`, not a test-tuned threshold. Retrieval uses the full author test gallery, including singleton gallery images, averaging over eligible query images.

## Remaining differences

| Area | Difference / implication |
|---|---|
| Hardware/runtime | Existing Windows/RTX4090, torch2.7.1/torchvision0.22.1/CUDA12.6 instead of the older original framework/GPU. A seed cannot establish identical floating-point optimization across environments. |
| Framework | Explicit PyTorch loops rather than the original Lightning version. Model/loss/schedule settings are matched and tested; framework execution is not byte-identical. |
| RNG | Original block-sampling rules tested against author functions, but explicit epoch-seeded generators change the complete RNG call sequence. Mid-epoch worker augmentation streams are not bitwise continuous on resume. |
| Memory | Non-reentrant activation checkpointing on the trainable retrieval backbone, with RNG preservation and BN-buffer restoration. Small CPU equivalence checks passed; full-GPU numerical equivalence not measured here. |
| Logged loss | Verification epoch training loss is sample-weighted, while author logging averages batch means. Display can differ slightly; selection uses batch-mean validation loss. |
| Retrieval evaluation | Chunked normalized squared-L2 NumPy instead of FAISS/PML. Explicit exact-image diagonal exclusion. Original code removes the first neighbor assuming it is self; duplicates/ties can differ. |
| Tie handling | Deterministic distance-then-filename ordering plus tie counts and expected random-tie Rank1. Original FAISS tie order was not a cross-platform contract. |
| AUC CI | 10,000 pair-bootstrap attempts, seed3. Original last-index-excluding sampling bug is not copied. It is a pair-level, not patient-cluster CI, and can differ from publication. |
| Input integrity | Exact manifest and file-presence checks, not a full raw-image pixel hash pass. Original duplicates retained for fidelity. Altering source bytes can affect results. |
| External cohort | COVID only; no CheXpert/additional external ablations. Not every table in the publication is reproduced. |

The earlier draft's approximate custom cross-batch loss is **no longer used**. The original vendored PML can emit Python3.12 regex warnings and a torch.meshgrid future warning.

## Measurements, not guarantees

NIH reference: AUC0.9940; verification Accuracy0.9555; retrieval P@1=0.9963, mAP@R0.9748, R-Precision0.9763.

These are paper references, not an asserted result of this package. `evaluation_results.json` records actual measurements and differences. Rounding equality to four decimals does not establish experimental equivalence. No invented tolerance, cherry-picked seed, fabricated success flag or automatic test-set tuning is used. Starting the blur stage does not certify that baseline quality is equivalent; review the measured comparison.

## User extension

Baseline weights and test manifests stay fixed. Only query processing changes; original galleries remain fixed. Levels0/1/2/4/8/16/32/64/128/256 operate in source-image pixels before model resize. No transformed test condition tunes baseline training.

One preselected source per dataset produces original1+blur10+mosaic10 PNGs under `대표사진` (42 total). Selection precedes model results. Blur preserves Pillow GaussianBlur radius; mosaic preserves BOX-downsample/NEAREST-upsample. Identity rows original/blur0/mosaic0/mosaic1 transparently reuse measured baseline results; all nonidentity conditions run inference.

PrivacyScore@1=100×(1−P@1) is a descriptive empirical attack-failure complement, not formal anonymization, a non-reconstruction proof or clinical-task utility.
