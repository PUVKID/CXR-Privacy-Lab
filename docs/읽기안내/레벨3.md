## 현재 실행 정책 · 10차 처음부터

**7차 학습과 이전 대기열을 중단하고 보관했으며 10차 새 원본 original_000부터 시작합니다.** 원본 1·블러 10·모자이크 10의 21조건을 공통 ImageNet 초기값·시드3에서 각각 새로 학습합니다. 7차 완료를 기다리거나 이전 CXR 체크포인트를 넘겨받지 않습니다.

| 강도별 학습 |20조건 버튼과 새 원본 상세를 별도 조회 | 각 조건의 초기화·학습·같은 조건 평가만 결합 |

아래 이전 설명의 ‘7차 유지·원본 완료 대기’는 재시작 요청 이전 설계로 보존하며 현재 동작을 뜻하지 않습니다. 새 실행의 준비·학습·완료 여부는 실제 기록으로 확인합니다. 외부 GPU 프로세스 목록은 관측 정보이며 CXR 중복 실행을 차단하고 기존 단계별 메모리 여유 기준은 유지합니다. CPU 실변환 검사는 import 시간 상한으로 미완료이며 실제21조건 학습 완료를 주장하지 않습니다.


준비→학습→평가 순서로 확인합니다. **학습 실행 창과 조회 화면**의 역할이 다르므로 화면이 열렸다는 사실만으로 학습 중이라 판단하지 않습니다. 에폭·배치·저장 시각과 실제 실행 프로세스를 함께 확인합니다.

## LEVEL 3·10차 강도별 독립 학습

**원본 7차는 그대로 두고 10차의 학습 실행 안내를 따릅니다.** 실행 전 데이터와 공통 실행 환경, ImageNet 초기값, 현재 원본 실행의 식별자와 상태를 확인합니다. 시작 명령은 10차 학습 안내에 있으며, 대시보드는 읽기 전용이므로 화면 버튼을 눌러 학습을 시작하거나 종료하지 않습니다.

순차 실행기는 원본 학습·원본 평가·기존 변환 평가의 정상 종료를 기다립니다. 원본 관리자가 오류로 종료되거나 종료를 확인할 수 없으면 다음 조건을 학습 중으로 바꾸지 않습니다. 같은 대기열을 중복 실행하지 않으며, 원본 실행기나 Python 전체를 종료하는 것은 표시 창만 닫는 일과 다릅니다.

대시보드에서 원본 학습과 강도별 독립 학습을 나누어 확인합니다. 강도 목록의 조건을 선택하면 현재 단계, 에폭과 배치, 손실 기록, 초기화와 재개 정보를 확인합니다. 동일 조건의 중단 재개는 그 조건과 프로토콜이 일치할 때만 허용되며, 다른 조건의 체크포인트를 지정해 학습을 건너뛰지 않습니다.

원본 고정 모델의 블러·모자이크 평가는 기존 영역에서, 새 조건별 학습 상태는 독립 학습 영역에서 봅니다.

학습 시작 전·학습 진행 중·평가 전 상태에서 최종 성능을 읽어 내지 않습니다.

원비율·손실·학습률은 저장값을 유지하고 백분율 요약만 소수 첫째 자리로 반올림합니다.

의료 원영상·영상별 목록·가중치·운영 로그는 공개 저장소에 포함하지 않습니다.

## LEVEL 3·9차 학습 진행 화면

**7차 계산을 유지한 채 9차 화면을 여는 절차**입니다. 공개 사본에는 의료 자료·가중치·운영 원문이 없으며 로컬 연구 환경과 연결된 경우에만 실제 관측을 읽을 수 있습니다.

| 순서 | 확인할 내용 | 보고할 근거 |
| --- | --- | --- |
| 1 |9차 서버·화면과 7차 실험 연결 표시 | 다른 차수의 예전 화면과 구분 |
| 2 | 현재 학습 단계·프로세스·기록 시각 | 살아 있는 실행과 과거 로그를 구분 |
| 3 | 에폭·배치 원수와 에폭 막대 | 배치 분모를 확인한 해당 에폭의 진행률 |
| 4 | 단계 최대 에폭과 완료 근거 | 최대 예정량과 실제 조기 종료·완료를 분리 |
| 5 | 손실의 학습/검증 구분·표시 범위 | 최근 일부 이력인지와 마지막 관측 시각 |
| 6 | 두 테마·모션 정지·키보드·작은 화면 | 실제 조작 상태와 값의 출처를 함께 점검 |

9차 폴더에서 `node server.mjs`로 조회 서버를 실행하고 로컬 8787 화면을 확인합니다. 이미 같은 포트에 서버가 있으면 중복 실행하거나 학습 프로세스를 종료해 해결하지 않습니다. 현재 서버의 차수와 주소는 실제 실행 환경에서 대조합니다.

숫자가 비어 있거나 이력이 오래됐으면 미측정·확인 불가로 기록합니다.

손실을 정확도로 바꾸거나 이전 단계 곡선을 현재 단계 곡선으로 이어 붙이지 않습니다.

백분율 요약은 소수 첫째 자리 반올림이며 원수·원비율을 확인합니다.

표시용 창을 닫은 뒤에도 실제 학습 생존과 기록 증가가 이어지는지 따로 확인하고, 학습 실행기 전체 종료와 혼동하지 않습니다.

## LEVEL 3 · 실행 전 준비와 목적 선택

현재 작업을 재현하려면 **계산은 로컬 7차, 화면은 8차**라는 경로 계약부터 확인합니다.

공개 판에는 의료 데이터·영상 목록·가중치·운영 원문과 권한 미확인 엔진이 포함되지 않습니다.

문서에서 설명한 로컬 CMD를 공개 사본만으로 전부 실행할 수 있다고 가정하지 않습니다.

원본/패키지가 준비된 환경에서 아래 순서로 확인합니다.

| 순서·목적 | 실제 도구·자료 | 통과 조건 | 실패했을 때 |
| --- | --- | --- | --- |
| 1 환경 확인 | 7차 Check-CXR7.cmd/All-In-One.ps1 -Action check | 환경·공식 목록·필요 영상 존재 확인 | 원인과 원문 보존; 누락을 다른 파일로 대체하지 않음 |
| 2 실행 선택 | Start-CXR7.cmd 또는 Resume-CXR7.cmd | 새 UUID 시작인지 현재 실행 재개인지 명시 | 모델·설정·분할·환경 결합 불일치에서 재개 금지 |
| 3 설정 대조 | training_config.json·preflight.json | seed3·배치 32·원 목록·작업자16/4·출처 해시 | 실험 도중 설정을 바꿔 오류를 우회하지 않음 |
| 4 학습 확인 | progress.json·events.jsonl·실제 프로세스 | 검증 →검색 출력 부 →검색 전체 단계와 처리 배치 전진 | 과거 training JSON만으로 현재 실행 판정 금지 |
| 5 모델 선택 | 현재 runs/UUID의 선택 가중치·artifacts.json | 검증 best/검색 각 마지막 모델·SHA 일 치 | 다른 실행이나 공개 최종 CXR 모델 혼입 금지 |
| 6 기준 평가 | evaluation_results.json | NIH/COVID×검증/검색 실제 지표·분모 | 미측정은 미측정;시험 보고 재튜닝하지 않음 |

| 8 화면 확인 | 8차 node server.mjs·127.0.0.1:8787 | 화면 8차/실험 7차/읽기 전용·현재 UUID | 예전 6차 화면의 5차 제어와 혼동하지 않음 |

검증 모델은 256px·Adam1e-4·100에폭 상한·patience5로 확인합니다.

검색은 1024px·128차원·SGD momentum0.9·weight decay1e-5·OneCycle 최대 0.158489·출력부 30/전체 50에폭·CBM128·블록 8을 대조합니다.

같은 환자 쌍과 다른 환자 쌍의 생성 방식, 검증 음성 재생성, 검증 중 CBM 갱신을 설정 표의 숫자만큼 중요하게 기록합니다. 7차는 NIH 원본 112,120장·COVID 원본 781장을 씁니다. 3차는 중복 차단으로 준비가 실패했고, NIH112,086장 정제는 4차부터, COVID777장 정제는 5차부터 적용됐습니다. 6차는 5차 실험의 조회·제어 연결이며 이 파생 분모를 7차에 복사하지 않습니다.

화면에서는 데이터셋·과제 →단계 →강도를 선택하고 원값을 펼칩니다. 3초 갱신 후 선택·포커스·펼침이 유지되는지, 양쪽 테마·모션 재생/정지·작은 화면에서 글자가 잘리지 않는지 확인합니다.

최근 로그는 현재 실행의 가장 최근 stdout/stderr 쌍인지 봅니다.

정상 256KiB 앞부분 생략은 보조 안내이고 손상·다른 실행·읽기 실패는 오류입니다.

읽기 전용 화면의 선택과 모션 제어는 계산을 시작하거나 끝내지 않습니다.

백분율은 소수 첫째 자리 반올림과 전체 원비율을 함께 기록합니다.

반올림 100.0 과 정확히 1을 구분하고 AUC·손실·학습률 원값을 유지합니다.

Node·관리자·모델 CPU/GPU 회귀와 실제 전체 학습·성능 재현을 나눠 보고 합니다.

전체 학습·84 조건·논문 재현이 미확인인 상태에서 검사 통과를 최종 성공으로 바꾸지 않습니다.

오류·부분 결과·역사적 차수는 보존하며 의료 원본과 비공개 로그는 업로드하지 않습니다.
