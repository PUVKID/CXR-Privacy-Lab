# 학습 진행 시각화 설계와 작업계획

목표는 같은 7차 학습을 중단하지 않고, 얼마나 진행했는지 실제 기록으로 읽기 쉽게 보여 주는 것입니다. 8차 화면은 보존하고 9차 화면에 반영합니다. 기존 Node 서버와 순수 JavaScript 구조를 유지합니다.

| 화면 | 표시 기준 | 해석 |
| --- | --- | --- |
| 현재 에폭 | 현재 배치 / 에폭의 전체 배치 | 현재 자료 순회의 진행률 |
| 현재 학습 단계 | ((현재 에폭−1)+현재 배치/전체 배치)/예정 최대 에폭 | 최대 예정 에폭을 기준으로 한 수치, 전체 실험 시간 비율이 아님 |
| 학습 흐름 | 검증 모델 → 검색 출력부 → 검색 전체 | 저장된 완료 근거·현재 기록·실제 프로세스로 구분 |
| 손실 추이 | 저장된 정상 학습 기록과 검증 기록 | 실제 관측 구간·축·누락·마지막 기록 시각을 표시 |
| 진행 원값 | 배치·에폭·손실·학습률·원기록 | 표시를 위해 저장값을 바꾸지 않음 |

검증 모델은 최대 100에폭과 조기 종료 규칙을 가지며 검색 출력부는 30에폭, 전체는 50에폭입니다. 이 셋을 단순 평균한 값을 시간 완료율로 표시하지 않습니다. 실제 조기 종료·단계 완료를 예정 최대 에폭 도달과 구분합니다. 속도나 예상 시각은 유효한 연속 관측이 충분하지 않으면 미측정으로 둡니다.

- [x] 큰 진행 막대, 세 단계 상태, 실제 손실 그래프와 구간 안내를 구현합니다.

## 변경 경계와 검증

7차의 학습 코드·설정·가중치·실행 식별자와 기존 차수는 변경하지 않습니다. 대시보드는 읽기 전용을 유지하며 모션 정지는 학습 정지가 아닙니다. 기존 흰색·회청색, 나눔고딕 Bold 700, 다크 모드, 백분율 소수 첫째 자리 반올림과 원값 확인을 유지합니다.

정상 기록이 오래됐거나 현재 실행 프로세스가 확인되지 않으면 학습 중으로 단정하지 않습니다. 손실이 미측정이면 빈 그래프 안내를 표시하며 0으로 대체하지 않습니다. 손실 감소는 최종 재식별 성능이나 익명성의 증거가 아닙니다. 제한된 로그 꼬리로 그린 그림을 전체 학습 이력이라고 표시하지 않습니다.

## 구현자 확인 범위

Node29개 검사와 서버 문법 검사를 실행했습니다. 실제7차 기록을 읽기 전용으로 확인해 최근256KiB의 학습 손실 및 에폭 검증 손실이 전달되는 것을 확인했습니다. 그래프의 축 눈금만4유효숫자이며 점 설명과 전체 원값은 보존합니다. 실제 브라우저·운영 서버 교체·독립 검토·공개 반영 항목은 부모 담당으로 남겨 둡니다.

진행 막대의 요약 백분율은 원정수 분자·분모에서0.1% 단위로 직접 반올림합니다. 나눗셈 후 이진 부동소수 오차 때문에 경계값이 낮아지는 문제를 막고, 원비율과 저장값은 그대로 보존합니다. 2,100개 경계 조합과 별도 재현 사례를 검사합니다.
