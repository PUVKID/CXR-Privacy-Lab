# 7차 원 논문 정합성과 실행 재검증

2026-11-20 확인입니다. **7차는 저자 공식 구현을 기준으로 새로 학습하는 Windows 포팅**입니다. 공개 최종 CXR 가중치만 평가하는 경로가 아니며, 논문의 모든 환경·분석·성과가 같다는 결론도 아닙니다.

## 같다고 단정할 수 없는 부분

| 구분 | 차이 또는 남은 한계 | 해석 |
| --- | --- | --- |
| 본문과 공식 코드 | 본문은 같은 balanced validation/test를 설명하고 공식 RNP는 검증 음성도 재생성 | 7차는 공식 RNP 구현 경로를 따름 |
| 검증 메모리 | validation·sanity2배치가 같은 CBM 큐에 들어감 | 누수 방어를 강화한 새 설계라고 부르지 않음 |
| 중복 | 원 저자 목록의 동일 픽셀 중복을 제거하지 않음 | 자기 파일 제외만으로 모든 중복 영향 해소 아님 |
| 실행 환경 | Windows·RTX4090·PyTorch2·현대 torchvision | 역사적 런타임의 이진 동등성 미확인 |
| 수치·난수 | epoch seed·worker 재개·활성값 재계산·BN복원 | 전체 원본 난수 호출열과 동일하지 않음 |
| 평가 통계 | 결정적 동률·pair bootstrap 마지막 인덱스 버그 수정 | 원 FAISS 동률·원 bootstrap과 차이 가능 |
| 연구 범위 | CheXpert·모든 부가 분석은 미포함 | 전체 논문 재현 완료 아님 |

**원 논문 충실도와 더 엄격한 누수 방어는 구분해야 합니다.** 4~6차의 중복 제외·validation 큐 갱신 방어를7차에 몰래 혼합하지 않았습니다. 원본 기준 결과를 얻더라도 중복 보존과 메모리 혼입의 영향을 별도 해석해야 하며, 논문 수치와 같게 보이도록 시험 조건이나 허용 오차를 새로 고르지 않습니다.

global_step은 학습 단계 안에서 처리한 배치의 누적값입니다. 검색의 혼합정밀도에서 비유한 기울기로 optimizer 적용을 건너뛴 배치도 포함하므로, 실제 가중치 갱신 횟수와 같다고 추정하지 않습니다. 위 재개 관측은 FP32 검증 단계의 실제 처리 진행 증거입니다.

실패 순간 파일을 보유한 프로세스는 확인되지 않았습니다. Windows 파일 공유 충돌·보안 프로그램 등은 가능한 원인일 뿐 확정하지 않았습니다. 실패 뒤 종료 상태 기록은 성공했고 원본 파일의 영구 쓰기 금지를 확인한 것은 아닙니다. 원인을 추정해 학습 소스나 결합 검사를 약화하지 않고 기존 체크포인트로 재개했습니다. 미래의 모든 저장 오류·운영체제 종료를 방지한다는 보장은 아닙니다.
